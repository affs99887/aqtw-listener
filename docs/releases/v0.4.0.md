# v0.4.0 · 局内识别改造（便携预览版）

针对“仓库能识别、进入对局几乎不识别”的问题重做识别链路。62 条拿起参考、物品目录、浮窗和个人音效库不变；改动集中在起点检测、特征与门限。

- 识别引擎改为进程内的局内匹配器：起点锚定、扣除起点前约 300 ms 的背景频谱、只比对约 0.9–11 kHz 频带。局内混音的低频轰鸣不再压掉物品声，参考的静音区也不再被背景填满。
- 起点检测改看 700 Hz 以上的能量，背景取前 300 ms 的安静块，更响的前置声音不再屏蔽紧随的拿起声；起点估计偏早时匹配器向后搜索 128 ms。
- 组门限 0.82，五条短促或类噪声参考 0.90，自动单次结果 0.86。
- 已接受的拿起结果后 1 秒内出现的不同音效匹配（通常是同一物品的放下声像另一件的拿起声）记入历史但不替换浮窗。
- 不再启动 Go 工作进程；`soundradar` 与 `dtw` 引擎代码保留，可在 `library.json` 切换。`engineIndexSha256` 现绑定 `references.json`。

## 验证

- 五场完整录像便携 CLI 回放：行商 10 次拿起 10/10 产生候选（0.94–0.98），重复拖动同一货物候选一致；此前为 0/10。已确认的 10 处误报场景中 9 处不再输出。真实拖动 1/2 匹配正确音效簇。详见[局内识别复核](../INMATCH-VALIDATION-20260924.md)。
- 核心测试 33/33、应用与个人库测试 46/46；62 条参考经扫描器与匹配器全部可确认（此前 59/62）。
- 门限在同一批录像上校准，不是独立准确率验收；快速转移的双击界面音会显示红外线理疗灯候选，黎明拖动仍未匹配，见复核报告的限制一节。

## 使用与更新

退出程序后整体替换程序文件和 `library` 文件夹，保留自己的 `local-data`。此前启用的个人库版本仍是 `soundradar` 引擎，会继续沿用旧逻辑；请在个人库中回退到基础库，再重新建库以使用新匹配器。
