# v0.3.2 · 局内自动触发与拿起优先识别（预览版）

修复开启监听后，在持续游戏环境声中「声音分析次数不增加」的问题。事件门改为相对背景的短声起落，识别不再依赖末尾静音。

- 拿起声先判断，主窗口聚焦事件附近约 0.4 秒；匹配成功立即保留，不等待放下，也不再被稍后长窗口的不同声音推翻。
- 自动监听期间的鼠标点击不再取消或推迟声音分析。鼠标专用路径同样在首轮匹配后结束，不继续等待一秒长窗口。
- 放下声通过独立辅助库确认近期同组的拿起结果，只添加确认状态，不创建或替换候选、分数和拿起录音。现有 4 组 / 5 条放下参考，没有覆盖的组仍可只靠拿起声识别。
- 新增 `Listener.Cli scan 库.json 音频.wav 报告.json`，可在本地复现连续音频的触发与匹配；报告不含原始音频。

## 下载与更新

下载 `AqtwListener-v0.3.2-win-x64.zip`，解压运行 `AqtwListener.exe`。更新时保留自己的 `local-data`。本版继续只采集 `UAGame` 及其子进程的声音，统一监听浮窗与布局保持。

## 验证与边界

核心测试 29/29、应用与布局测试 45/45、便携版 UI 检查通过，包括 14 条拿起参考、持续底噪触发、连续点击、5 条辅助参考、辅助结果保留与取消。

使用用户提供的两场完整对局，在本地截取共 610 秒行商、背包及走动声音回放。原先无分析的 37 秒行商操作段已能触发拿起分析；两段行商回放分别得到 21 次和 5 次匹配。数量不是正确率，神秘货物没有逐件揭示标签；背包片段仍有声音未收录或未匹配。

两个走动反例片段分别出现 0 次和 1 次物品匹配，后者在画面中对应包扎动作。自动单次匹配底线由实验目录的 0.75 增加到 0.78，但仍不能保证排除所有相似环境音。本次实录没有得到放下辅助确认，辅助路径通过来源参考与控制器测试验证，仍待更多实机样本核验。本版未完成实战准确率验收。

录像、截取音频、分镜和个人数据只留在本机研究目录，没有进入提交或发布包。测量记录见 `docs/measurements/inmatch-v0.3.2.json`。
