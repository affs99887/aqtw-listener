## 3. 用户已经确认的产品要求

- Windows 本地浮窗，供本人及少量朋友使用，无账号、无云端识别、无后台上传。
- 到达行商后用组合键开启，鼠标左键按下或开始拖动时识别，再按组合键关闭；默认 `Ctrl+Alt+L`，允许修改。
- 拾起与放下音效分开，首版主要识别拾起。长按拖动只触发一次，松开不另起识别；连续点击以最新操作为准。
- 切出游戏暂停采音并清空结果，切回恢复；手动关闭释放资源。正常使用不保存原始录音。
- 只读取系统音频、窗口状态、鼠标事件；不读取游戏画面、内存、数据包，不自动购买。
- **全部物品必须有缩略图，名称可以不显示。** 按占用格数分组，例如「1 格」「2 格」，并保留宽×高信息。
- 用户明确取消单件物品旁的百分比。只显示「大金候选占比」：去重红色收藏品候选数 ÷ 全部候选数；不是实际出货概率。空候选显示「—」，不能显示 0%。
- 不能为显示高价值物品而排除同音的低价值候选。分母按完整候选计算，不能随可见条目数变化。
- 最匹配候选与最高参考价值候选分开表达。参考价应使用有来源与日期的联络人回收价；当前价格全部为空，不能编造最高价值结论。
- 浮窗默认鼠标穿透、置顶、不抢焦点，位置、尺寸、透明度可调。独占全屏如有问题，可尝试无边框全屏，并如实记录兼容性。
- 用户要求复用 SoundRadar 加速开发，README 必须标注使用到的第三方仓库。

## 4. 架构与关键入口

采用 **C# / .NET 10 / WPF / NAudio.Wasapi 3.1.0 + 常驻 Go SoundRadar 核心工作进程**。原计划的 C# Log-Mel + DTW 保留为离线比较基线，默认实时引擎是 SoundRadar DSP 与量化索引。

```text
所选播放设备 WASAPI 回环
  → 带时间戳的短时内存缓冲
  → 左键按下，生成操作编号，预留约 60 ms 前置声音
  → 450 ms / 1080 ms 两阶段调度
  → 常驻 Go 引擎：降噪、Log-Mel、量化索引匹配
  → 展开全部过门限音效组，按物品编号去重
  → 复核操作编号及前台状态
  → WPF 按格数展示缩略图与大金候选占比
```

| 文件 / 目录 | 职责 |
|---|---|
| `src/Listener.App/ListeningController.cs` | 启停、前台状态、设备协调、两阶段调度、取消及旧结果失效 |
| `src/Listener.App/LoopbackAudio.cs` | NAudio 系统回环采音与时间戳缓冲写入 |
| `src/Listener.App/NativeInput.cs` | 组合键、鼠标及前台窗口事件；输入回调不得做耗时识别或绘制 |
| `src/Listener.App/MainWindow.cs` | 主窗口、设置、托盘、预览及诊断入口 |
| `src/Listener.App/Presentation.cs`、`Theme.xaml` | 候选展示、浮窗视觉与样式 |
| `src/Listener.App/Settings.cs` | 设置定义；默认浮窗 470×720、透明度 0.94、不显示名称、软件渲染 |
| `src/Listener.Core/Models.cs` | 音效库、候选、识别状态与结果契约、OperationEpoch |
| `src/Listener.Core/RadarRecognizer.cs` | 常驻 Go 子进程通信、结果转换和引擎选择 |
| `src/Listener.Core/Recognizer.cs`、`AudioFeatures.cs` | C# DTW 基线与特征提取 |
| `src/Listener.Core/AudioTimeline.cs`、`ClickLatch.cs` | 时间戳缓冲、鼠标锁存 |
| `src/Listener.Core/Evaluation.cs` | 校准、评测、来源隔离和验收门槛 |
| `src/Listener.Cli/Program.cs` | build / match / evaluate / calibrate / coverage 命令 |
| `src/Listener.Engine/cmd/listener-engine/main.go` | 新增 Go 工作进程协议及索引构建入口 |
| `src/Listener.Engine/internal/` | 复用的原始 DSP/index/library/wav 实现及测试 |
| `data/library/` | 版本化目录、声纹索引、51 张缩略图与素材来源 |
| `tests/Listener.Tests/Program.cs` | C# 核心规则测试，可执行程序式测试入口 |

Go 引擎在进程生命周期内复用，通过标准输入输出传递内存音频，不逐次启动，不监听服务端口，不写音频文件。前台事件配合 100 ms 状态检查；取消令牌与操作编号共同防止旧结果覆盖新结果。

当前组合版参数：匹配阈值 0.75、点击窗口静音门限约 -82 dBFS、240 Hz 高通。高通参数在派生工程样本上选择，仍需独立校准。索引与查询必须使用相同 DSP 配置；目录与索引有 SHA-256 绑定，更新时整体替换 `library`。

## 6. 本机构建、测试和使用

已具备的本机工具：`.tools/dotnet/dotnet.exe`（10.0.401）、`.tools/go/bin/go.exe`（1.27.1）、Python 3.11、Git 2.37.0。`.tools` 不在仓库或源码包中。其他开发机需自行安装 .NET 10 SDK、Go 1.27.1 和 Python 3。

在仓库根目录执行，适用于当前机器：

```powershell
$env:DOTNET_CLI_HOME = Join-Path $PWD '.tools\cli-home'
$env:NUGET_PACKAGES = Join-Path $PWD '.tools\nuget'
$env:DOTNET_CLI_TELEMETRY_OPTOUT = '1'

.\scripts\build-engine.ps1
.\.tools\dotnet\dotnet.exe run -c Release --project tests\Listener.Tests -- artifacts\core-tests-current.json

$env:GOCACHE = Join-Path $PWD '.tools\go-cache'
$env:GOPATH = Join-Path $PWD '.tools\go-work'
$env:GOTOOLCHAIN = 'local'
$goExe = Join-Path $PWD '.tools\go\bin\go.exe'
Push-Location src\Listener.Engine
try { & $goExe test ./internal/... } finally { Pop-Location }

.\scripts\publish.ps1
```

`data/engine/Listener.Engine.exe` 被 Git 忽略，新拉源码后必须先运行 `build-engine.ps1`。两个构建脚本在本地 `.tools` 不存在时会尝试 PATH 中的工具；以上手写命令中的 `.tools` 路径需相应替换。

便携包输出目录为 `artifacts/portable`。运行时个人设置在程序目录 `local-data/settings.json`，不应提交或打入分发包。没有默认游戏进程，需要在主窗口选择或填写不带 `.exe` 的目标进程名。

离线命令示例（参数中的音频与数据集路径需换为真实文件）：

```powershell
.\artifacts\portable\Listener.Cli.exe match data\library\library.json sample.wav
.\artifacts\portable\Listener.Cli.exe evaluate data\library\library.json dataset\test.json artifacts\evaluation.json
.\artifacts\portable\Listener.Cli.exe calibrate data\library\library.json dataset\validation.json artifacts\calibrated-library.json
```

诊断入口：`AqtwListener.exe --ui-smoke`、`--audio-smoke`、`--performance-smoke`。先退出已有助手，避免单实例互斥影响诊断。诊断会在程序目录写 JSON/截图；打包前检查并排除本次诊断文件和个人设置。正常使用不自动运行这些诊断。

## 8. 下一阶段建议顺序与验收要求

1. **素材与同音组验证**：优先逐件采集同音低价值物品、确认拾起/放下区别，补充未知物品、队友语音、枪声、持续环境声、静音与不同音量。记录来源、时间段、版本和操作类型。
2. **来源隔离与校准**：参考、validation、test 按原始录制来源隔离；转载、裁剪、变速、增益、加噪版本不得跨集合。工具能检查编号和哈希重叠，不能代替人工核实来源。只在 validation 上选参数，冻结后再测试。
3. **独立验收**：至少 200 个独立事件，至少 100 个非大金或干扰事件。目标为候选命中 ≥95%、唯一结论正确率 ≥95%、非目标误报 ≤5%；同时报告候选数量分布与唯一结论比例。
4. **端到端与输入可靠性**：记录鼠标按下至实际 UI 展示时间，目标 P95 初步结果 ≤1 秒、稳定结果 ≤1.5 秒。重点验证快速连点、长按拖动、切出/切回、启停，不串结果且不影响游戏输入。
5. **设备、系统与显示兼容性**：耳机切换和拔插、Windows 10/11、朋友电脑、常见分辨率、DPI、多屏、窗口/无边框/独占全屏。记录真实观察，不将桌面属性检查当成游戏覆盖验证。
6. **性能与产品打磨**：在真实监听负载下测 CPU/GPU/内存、点击延迟、长时间运行和低配机表现，再决定是否移植或合并引擎。继续检查缩小浮窗后的候选可见性，保持占比按全部候选计算。
7. **下一版发布工程**：参数化版本、整合许可证复制、干净 staging、源码 archive 与哈希校验，最后在朋友电脑验证便携包。

不需要等到所有数据齐全才开始设备或输入测试，但每类结果必须标清测试范围。仅完成离线验证时，不得标注实战达标。
