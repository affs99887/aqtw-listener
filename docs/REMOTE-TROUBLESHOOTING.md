# 远程操作与无响应排查

声音自动识别针对“拖动后完全没有反应”的输入与诊断链路。后续历史记录版还修正了两组拾起素材的错误禁用，见 [素材复核](COVERAGE-REVIEW.md)。未改变匹配阈值。UU 是否影响当前机器的鼠标或声音，需要根据实际诊断数据判断。

## 先试一次

1. 在游戏所在的被控电脑启动新版助手。目标进程固定为暗区突围 `UAGame`；播放设备仅决定试听去向。
2. 点击开启监听，切回游戏。浮窗顶部应显示“正在监听 · UAGame 进程声音”。
3. 保持“声音自动识别”勾选，拖动货物。即使“鼠标触发”一直是 0，只要音频有效，“声音分析 N 次”也应增加。
4. 若没有触发，回到助手点击“3 秒后试识别”，立即切回游戏，在倒计时结束时拖动一次。此功能仍遵守游戏前台限制。

## 看什么

| 显示 | 含义与处理 |
| --- | --- |
| 监听未开启 | 首次保存设置并不会自动开启；点击开启按钮或使用设置中的快捷键。远程端可能没有把组合键送到被控端，可先用按钮。 |
| 已暂停，当前前台不是游戏 | 目标固定为 `UAGame`。切回助手查看设置时暂停属于正常行为，切回暗区突围会恢复。 |
| 鼠标事件或备用触发增加，但已接受次数不增加 | 输入已被接收；检查是否开启监听、目标是否在前台、采音是否准备完成。导出的 `lastIgnoredReason` 记录最近未接受的原因。 |
| 两种输入计数都不增加 | 开启“声音自动识别”，由音频直接驱动识别。输入缺失原因可能涉及远程输入方式或 Windows 权限，单凭截图不能确定。 |
| 声音分析次数增加，显示暂未匹配 | 已实际执行识别，当前声音没有通过已收录音效组的匹配阈值。并非所有仓库物品都已收录。 |
| 已收到声音，但声音分析次数仍为 0 | 确认自动识别已勾选且游戏在前台；仍不增加时导出诊断，其中包含音频窗口幅度和自动识别状态。 |
| 已收到触发，但没有听到声音 | 检查游戏物品音效及游戏音量。采音绑定 `UAGame` 进程，不受试听播放设备选择影响。 |
| 暂未收到音频包 | 游戏进程尚未产生可采集声音；静音时也可能不回调，不能仅据此断定采音损坏。播放游戏声音后再看。 |
| 已收到音频包，当前静音 | 有数据但近期未检测到有效幅度，检查游戏音量。 |
| 未匹配，请再听一次 | 触发和识别已执行；可能是未覆盖物品、放下音效、干扰或阈值问题，需要实际样本判断。 |
| 采音错误 | 错误会保留显示，不再立即被“监听已关闭”覆盖。进程回环需要 Windows 10 build 20348 或更新版本；无法启动时不会退回混合系统声音。 |

浮窗完全不可见时，先根据原版说明使用无边框窗口模式，并检查监听是否开启。部分远程软件对透明置顶窗口的传输行为仍需实测。切回助手后，“最近识别”和已接受次数保留，便于排查。

## 诊断文件

“导出诊断”写入程序目录下 `local-data/diagnostics-时间.json`。包含前台/目标进程名、实际采音进程 ID、试听播放设备、启用状态、数据包计数、近期声音幅度、输入计数、最近接受的触发来源和识别结果，以及自动识别开关、分析次数、状态与最近窗口的 RMS。不会保存音频、鼠标坐标、键盘内容或游戏画面，也不会上传。

导出时前台一般是助手，因此 `capturing: false` 并不能单独说明游戏期间未采音；请结合保留的触发时间、识别结果和音频计数。当前音频计数在每次启动采集时归零。

## 实现依据与局限

- 声音自动识别每约 550 ms 取最近 1.15 秒的重叠音频窗口，等待 80 ms 的采音包到达后分析。只在游戏前台、有有效幅度且识别器空闲时启动；正常鼠标识别优先。已接受候选显示时间并保留至下一次有效匹配或手动清除；切出后尚未完成的任务仍被取消。历史在本次运行内保留最近 100 条。
- 鼠标钩子仅更新去重状态并排队，避免在本机输入回调中进行进程查询或取消识别。Windows 要求低级鼠标钩子及时返回，超时可能移除钩子：[Microsoft LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)。
- 每 25 ms 补查主鼠标按键的当前状态，仅使用最高位，不依赖“自上次查询以来按过”的最低位；映射左右键交换设置：[Microsoft GetAsyncKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate)。
- 鼠标事件和状态检测共用按下锁存，短暂延后接受与刚到达事件冲突的按键状态，减少重复识别。纯备用检测可能漏掉短于轮询间隔的点击，长按拖动更适合验证。
- 游戏采音只包含 `UAGame` 及其子进程，独立的 Discord／QQ／UU 语音不会进入缓冲；由游戏进程自身播放的队友语音仍可能进入。当前修复不保证所有 UU 版本、权限组合或游戏音频路由都已兼容。
