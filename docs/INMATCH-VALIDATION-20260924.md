# 2026-09-24 局内识别改造与录像复核 · v0.4.0

**结论：局内拿起识别从 0/10 提升到 10/10（行商拿起，全部在 0.94–0.98），此前 10 处已确认误报中 9 处不再输出。仍不是独立准确率验收：门限在同一批录像上校准，隐藏货物身份不能核实。**

## 为什么此前在局内几乎不能识别

对 9 月 20–22 日五场完整录像逐事件分析（原始 48 kHz 解码，不是此前的 24 kHz 提取）后确认三个叠加原因：

1. **低频主导**。62 条参考在约 600 Hz 以下几乎没有能量，能量集中在 2–11 kHz；而对局里的混音随时带有脚步、轰鸣和房间底噪，600 Hz 以下常常是整段音频里最响的部分。旧特征以整段 187 ms 片段的峰值为基准做 -20 dB 地板，低频背景成为峰值后，物品声自己的高频特征被压到地板，余弦相似度随之崩塌（已知物品最高只有 0.14–0.51）。原 240 Hz 二阶高通远不足以消除这一影响。
2. **背景填满模板的静音区**。参考只有 60–330 ms 有声，模板窗口其余部分是地板；局内同一区域被持续背景填满，即使物品声本身清晰也会被判为不同。
3. **起点检测被宽带能量牵制**。旧扫描器按宽带 RMS 找起点，行商界面里物品声比宽带背景只高约 5 dB（比 700 Hz 以上背景高 20 dB 以上），且更响的前置声音会把 0.32 s 内的真实起点全部屏蔽。

同时确认：所谓“搜刮快速转移”事件（原报告 8 次已标注操作中的 6 次）实际播放的是间隔约 40 ms 的双击界面音，不是物品拿起声，此前把它们当作正例是标注口径问题；两次真实拖动中的一次（彩蛋）在排除低频后即可匹配到正确音效簇。

## 改动

- 新增 `Listener.Core/InMatchRecognizer.cs`（`primaryEngine: "inmatch"`）：起点锚定、扣除起点前约 300 ms 的逐带中值背景谱、只比对 64 个 Mel 带中的第 16–55 带（约 0.9–11 kHz）、32 帧（187 ms）窗口、-20 dB 窗内地板、起点估计前 32 ms 到后 128 ms 的非对称搜索。特征在进程内计算，不再经由 Go 工作进程；`soundradar` 与 `dtw` 引擎代码保留，可通过 `library.json` 切换。
- `AutomaticAudioScanner`：起点改在 700 Hz 二阶高通后的 20 ms 块能量上判定；背景取前 300 ms 中第 2–4 安静块的均值；峰值只在起点后 160 ms 内取；不应期 0.25 s；起点后需等到 0.36 s 音频到齐。
- `PickupRecognition`：单次起点锚定分析，自动单次结果最低 0.86；不再做第二次长窗口复核。
- `RecognitionHistory`：已接受的自动拿起结果之后 0.15–1.0 s 内出现的**不同**音效匹配，记入历史但不替换浮窗（分数明显更高时除外）。回放显示同一物品的放下声会稳定匹配到另一物品的拿起参考：激光指示模块→天线、量子F2000 簇→红外线理疗灯、专用电池组→水壶。
- `data/library/library.json`：`primaryEngine` 改为 `inmatch`，组门限 0.82；耐冲击硬胶、军用电台、干花书签、硝化棉、红外线理疗灯五条在随机声音上大量出现 0.75–0.90 分数，门限设为 0.90。`engineIndexSha256` 改为绑定 `references.json`。个人库新组默认门限随引擎为 0.82。

## 已知限制

- 门限用这五场录像校准；未参与校准的对局尚未复核。不能宣称独立准确率。
- 黎明拖动（dawn-drag）仍未匹配：其正确音效簇在起点处只得 0.54–0.59，前 0.1 s 有更响的其他声音，且可能是同类音效的另一变体。库中每件只有一条参考，无法覆盖游戏中的随机变体。
- 快速转移的双击界面音与红外线理疗灯参考结构一致（弱起音加一声亮点击），在搜刮时会显示红外线理疗灯候选；提高该组门限无法区分两者。若觉得干扰，可在 `library.json` 中把 `peer-047` 的门限改为 1.0 关闭该条。（v0.4.3 更正：`peer-047` 本身就是琥珀天心类物品的放下／快速转移声，已改为关联整类物品，见[放下声更正](PUTDOWN-RELABEL-20260924.md)。）
- 激光指示模块簇（8 件电子类物品）在背包操作中频繁出现，游戏很可能对更多电子类物品使用同一音效，属于目录覆盖问题而非匹配错误。金魔方拿起匹配到金杯组同理。
- 24 kHz 或更低的采音格式下，钻戒、宝石项链、卡莫纳之星的高频内容被截去，自匹配约 0.82；现有 44.1/48 kHz 进程回环不受影响。
- 便携 ZIP 仍附带 Go 引擎文件供 `soundradar` 引擎选项使用，默认不再启动该进程。
