# 行商听音助手 · Windows 预览版 v0.4.0

按格数展示候选缩略图的本地听音浮窗：拿起物品时识别其音效，列出同音候选及每格大红概率。版本变化见 [docs/releases](docs/releases)。

## 项目来源与致谢

识别（`src/Listener.Core/InMatchRecognizer.cs`）、起点检测、候选去重、按格数计算的大红候选比例、桌面界面和评测流程由本项目实现。

## 开始使用

1. 打开项目的 `portable` 文件夹，双击 `AqtwListener.exe`。无需解压，也无需安装 .NET。
2. 先启动暗区突围，助手固定识别 `UAGame`，无需选择进程。播放设备设置只决定浮窗回放与参考音效的试听去向，不影响游戏采音。首次保存后需要开启监听；已开启时保存会保留启用状态，切回游戏后恢复采音。旧设置中的进程名不再使用。
3. 到达行商，切回游戏后按 **Ctrl+Alt+L** 开启监听，也可以先在主窗口点击开启。默认开启「声音自动识别」，拿起物品发出声音后自动分析，不必等待放下。开启自动识别时鼠标事件只计入输入诊断，不会中断或推迟声音分析；关闭自动识别后仍可使用鼠标触发。
4. 再按一次组合键关闭。切出游戏会暂停采音并隐藏浮窗，切回后恢复。识别成功后继续监听下一次声音，无需先手动关闭浮窗；已匹配结果持续保留，直到下一次有效匹配或点击「清除当前结果」。主窗口最小化后从系统托盘打开；关闭主窗口会退出助手。

主窗口按「监听／采音／位置／浮窗／音效库／诊断」切换，无浮窗预览。监听浮窗在游戏画面顶部居中，上边距约 16 逻辑像素。按 **Ctrl+Alt+L** 开启持续采音后，实时识别结果直接显示在唯一的监听浮窗中：顶部回放、停止、保存 WAV 和逐件试听始终保持同一布局。点击回放或试听会自动暂停采音，点击「返回监听」继续；**Ctrl+Alt+C** 也可主动进入或退出操作状态。7–20 件候选优先向下排布，宽度约 830–910 逻辑像素；极端更多候选才按需要加宽，最多为游戏画面的 94% 或 1600 逻辑像素。候选卡片一页看全，不分页、不使用滚轮；缩略图不会缩到 80 逻辑像素以下，六件示例使用 112 逻辑像素。浮窗顶部可切换小／中／大字号，物品名称与音效组匹配度始终显示。

浮窗在监听时允许点击控件而不主动抢走游戏焦点；回放或试听会切到暂停采音的操作状态，避免把播放声再次识别为新货物。右上角同一个图钉亮起表示固定、灰暗表示解锁，灰暗时仍可点击；解锁后拖动标题空白处自动保存位置。Esc 取消移动或退出操作，标题右键菜单可恢复居中及打开历史。退出操作时停止播放、清空采音缓冲并等待 300 毫秒，再按开关和游戏前台状态恢复。底栏没有「展开相近音效」开关，仅展示有效候选与录音选择。

候选总数按去重后的全部结果计算；每个格数分区单独显示「大红概率」，只用该格的候选作为分母，相近参考音效不参与计算。高分、与次名拉开差距且只有单件关联的音效标为「精确识别」；低分候选可标为「疑似」，不显示「同音候选」标签。匹配度只表示音效相似度，不是单件确定率或实测正确率。识别中显示加载动画并保留上次结果；未匹配或分析失败时显示「识别失败」，旧结果明确标注。

「识别历史」以连续列表保留本次运行最近 100 条，支持「在浮窗中对比」。最近 20 个有效声音片段及历史音频共用 32 MiB 内存上限，淘汰最旧且未选中的音频、保留文字；退出清空普通音频和本次历史，手动保存才写 WAV。每段声音绑定当时结果、全库评分及库版本。

「补库 / 学习」支持已有物品补样本、导入 WAV、试听裁剪、新物品名称/分类/格数及可选图片和参考价。引导学习需先选定物品，三轮参考加一轮单独试识别；每轮 3 秒准备、1.2 秒采音，**拿起并保持，采音结束后再放下**。无效轮次补录，切出暂停，可保留草稿续录。检查通过自动启用，失败保留原库；同音冲突需用户确认，普通识别不会自动成为训练标签。

个人资料与基础库分开，位于 `local-data/personal`，支持启停、删除、重采样、导入导出和撤销更新。发布包不含个人录音或设置；更新程序请保留自己的 `local-data`。详细操作、数据约定与验证边界见 [本版说明](docs/TOP-OVERLAY-PERSONAL-LIBRARY.md)。

### UU 远程或拖动没有反应

助手与游戏需要运行在同一台被控电脑。如果浮窗显示「鼠标触发 0 次 · 已收到声音」，请保持「声音自动识别」勾选。开启监听且游戏在前台时，新版直接从近期音频中识别，浮窗的「声音分析 N 次」会增加；鼠标事件仍使用事件与按键状态两路检测。

自动识别按 700 Hz 以上的近期背景声检测短声音的起落，无需窗口末尾静音；更响的前置声音不会屏蔽紧随其后的拿起声。检测到起点后等待约 0.36 秒音频到齐，再以起点为锚分析拿起声：扣除起点前约 300 ms 的背景频谱，只比对约 0.9–11 kHz 频带，起点估计偏早时向后搜索 128 ms。自动单次结果要求至少 0.86 的音效匹配分，目录组门限为 0.82（五条短促或类噪声参考为 0.90）。结果通常在放下前后出现。

不使用放下音效库。已接受的自动拿起结果之后 1 秒内出现的**不同**音效匹配，会记入识别历史但不替换浮窗，除非分数明显更高：录像回放显示同一物品的放下声会稳定匹配到另一物品的拿起参考（如激光指示模块→天线）。未匹配的后续声音同样不替换已接受的结果。

同一事件不会重复分析，也不累计任务。环境音、界面音仍可能触发分析；搜刮时的快速转移双击音会显示红外线理疗灯候选，第一人称移动或瞄准偶有 0.85–0.90 的误报，详见[局内识别复核](docs/INMATCH-VALIDATION-20260924.md)。

监听控制区固定显示前台进程、输入计数、采音状态及最近识别结果。先确认已开启监听，再切回 `UAGame`；采音绑定游戏进程及其子进程，不依赖选定的试听播放设备。Discord、QQ、UU 等独立软件在同一设备播放的朋友语音不会进入游戏采音；如果语音由游戏进程自身播放，仍会进入录音，需要另行处理。

可点击「3 秒后试识别」，立即切回游戏，在倒计时结束时拖动一次货物。这会主动触发一次识别，帮助检查音频链路。仍无法定位时点击「导出诊断」，生成 `local-data/diagnostics-*.json`；文件仅包含状态与计数，不保存录音。详细说明见 [远程排查](docs/REMOTE-TROUBLESHOOTING.md)。

默认使用适合静态浮窗的软件渲染以降低内存占用；高分辨率下绘制不流畅时可在「浮窗」设置中启用硬件加速，重启生效。

候选按格数分区，每个格数独占整行区域；标题直接写「2 格」「4 格」等。单行 1／2 件采用横向信息卡与固定宽度试听按钮，3／4 件采用紧凑等宽卡；更多候选均衡分行，避免最后一件被拉满整行。卡片突出完整物品名称与匹配度，同时显示缩略图、具体宽×高和大红标记。同一音效组内的物品可能显示相同匹配度，该数值不是单件确定率。参考价完整时会标出已知参考价最高的候选。

**某格大红概率 = 该格去重后大红候选数 / 该格全部候选数。** 例如 4 格候选中 2/3 件为大红，界面显示 67%。这是候选比例，不是游戏实际出货概率；顶部不再显示跨格数的总百分比。

## 当前数据边界

- 基础库现有 **62 件物品、62 条拿起参考**，按每件原始参考建立索引组。62 条参考并非 62 种独立声音，完全相同及近似的参考均保留，一声可命中多件。当前库不是旧库 51 件的超集，没有参考的旧条目不再凭旧同音映射加入候选。
- 34 件沿用已核实的旧目录格数、物品 ID 和缩略图；28 件新增目录使用来源物品图，格数依据背包格网检查或用户确认。逐件记录见 [覆盖清单](docs/COVERAGE.md) 和 `data/library/provenance.json`。
- 完整参考自身匹配通过，不等于实战通过。62 条参考经扫描器与匹配器全部可确认；每件仅一条参考，游戏内同类音效的随机变体可能匹配不到，黎明拖动即为一例。
- 「双颈琴」未在当前目录中找到，不能自动认定为「里拉琴」；用户所称「琥珀天星」与目录名「琥珀天心」也仍需实机对应确认。库外物品需要补充真实音效与物品资料。
- 价格未取得可靠的当前联络人回收依据，全部留空；目前不会伪造最高价值结论。可在 `library/library.json` 中为物品补充 `referenceValue`、`valueSource`、`valueDate`，重启生效。
- 门限按 9 月 20–22 日五场完整录像回放校准，没有独立验证集；不能宣称达到 95% 准确率。
- 局内低频轰鸣、脚步和房间底噪对匹配的影响已在上述录像中确认并处理；队友语音、枪声与库外物品的更多对局仍需另行实机复核。

详情见 [覆盖清单](docs/COVERAGE.md)、[方案比较](docs/ARCHITECTURE.md)、[测试报告](docs/TEST-REPORT.md)。

## 软件行为

采集 `UAGame` 及其子进程的 WASAPI 进程回环音频，不采集其他独立软件的播放声，不开麦克风，不读取游戏画面、内存或网络包。需要 Windows 10 build 20348 或更新版本；不支持进程回环时会停止识别，不会退回包含语音软件的系统混音。普通识别音频只保留在内存；手动保存和明确开始的学习录音才写入本地。暂停监听释放采音流并清空采音缓冲，历史回放缓存保留至退出。没有账号、上传、自动更新和自动购买。

独占全屏覆盖尚未验证。浮窗看不见时，先将游戏改为无边框全屏；Windows 11、朋友电脑和不同分辨率仍待实测。

更新时退出软件，整体替换 `library` 文件夹或程序包。目录与参考音频清单有 SHA-256 绑定（`engineIndexSha256` 对应 `references.json`），混用不同版本会明确报错。个人设置存放在程序目录 `local-data/settings.json`。

## 源码与构建

桌面：C# / .NET 10 / WPF / NAudio.Wasapi 3.1.0。识别在进程内完成（`InMatchRecognizer`），参考模板在启动时由 `library/audio` 计算，无索引文件，也不启动其他进程。

需要 .NET 10 SDK 和 Python 3；便携包使用者无需这些环境。SDK、缓存、IDE 配置和编译产物不提交到仓库。构建脚本优先使用本机 `.tools` 下的工具，不存在时使用已安装并加入 PATH 的工具。

```powershell
dotnet run -c Release --project tests\Listener.Tests -- docs\measurements\core-tests.json
dotnet run -c Release --project tests\Listener.App.Tests -- docs\measurements\controller-tests.json
.\scripts\publish.ps1
```

发布脚本固定更新项目下的 `portable`，只保留这一份最新便携程序，不创建版本目录或压缩包。后续更新覆盖程序文件，保留 `portable/local-data` 中的设置、录音、草稿和个人音效库。GitHub Release 附件单独打包为无个人数据的 ZIP。

离线工具：

便携包内也包含 `Listener.Cli.exe`，可直接使用以下参数；源码环境才需要 `dotnet run`。

```powershell
dotnet run -c Release --project src\Listener.Cli -- match data\library\library.json sample.wav
dotnet run -c Release --project src\Listener.Cli -- scan data\library\library.json gameplay.wav events.json
dotnet run -c Release --project src\Listener.Cli -- evaluate data\library\library.json dataset\test.json report.json
dotnet run -c Release --project src\Listener.Cli -- calibrate data\library\library.json dataset\validation.json calibrated.json
```

样本格式、更新流程和来源隔离见 [数据工作流](docs/DATASET.md)。
